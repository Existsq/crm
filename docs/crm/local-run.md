# Локальный запуск CRM

Как поднять relay и десктоп-приложение на своём компьютере и пройти CRM-сценарии.
CRM-функции разрабатываются цепочкой веток: каждая следующая содержит всё из
предыдущих. Смотрите самую свежую ветку из списка ниже.

| Ветка | Что в ней видно |
|---|---|
| `crm/foundation` | relay, CLI `buzz crm space …` (без UI) |
| `crm/desktop-shell` | раздел **CRM** в приложении: создание CRM-пространства, настройки, склады |
| `crm/catalog` | раздел **Товары**: список, поиск, создание и редактирование, архив |

## 1. Что нужно установить

- **macOS** или **Linux**. На Windows запускайте всё внутри WSL2 (Ubuntu); окно
  приложения откроется через WSLg.
- **Docker** 24+ (Docker Desktop на macOS/Windows). Он нужен для Postgres, Redis
  и MinIO.
- **git** и около 20 ГБ свободного места под сборку Rust.
- **Только Linux / WSL2**: системные библиотеки Tauri:

  ```bash
  sudo apt-get install -y --no-install-recommends \
    build-essential curl file libasound2-dev libayatana-appindicator3-dev \
    libgtk-3-dev librsvg2-dev libssl-dev libwebkit2gtk-4.1-dev libxdo-dev \
    patchelf wget
  ```

Rust, Node, pnpm и `just` ставить вручную не нужно: их версии закреплены через
Hermit и скачиваются при первом запуске.

## 2. Скачать код и подготовить окружение

```bash
git clone https://github.com/Existsq/crm.git
cd crm
git checkout crm/catalog        # или другая ветка из таблицы выше

. ./bin/activate-hermit         # в каждом новом терминале
just setup
```

`just setup` создаёт `.env`, поднимает Docker-контейнеры, применяет миграции
(включая CRM-таблицы `crm_*`), регистрирует локальное сообщество и ставит
зависимости десктопа. Первый запуск долгий: Rust собирает зависимости.

**Если Docker пишет `401 UNAUTHORIZED` для `quay.io/minio/...`.** Образы MinIO на
quay.io больше не раздаются. Поднимите сервисы с образом MinIO, который
использует CI, и повторите `just setup` (он увидит, что Postgres и Redis уже
работают). Keycloak для CRM не нужен.

```bash
docker compose -f docker-compose.yml -f docker-compose.ci.yml up -d postgres redis minio minio-init
just setup
```

## 3. Запустить relay и приложение

```bash
just dev
```

Команда запускает relay на `ws://localhost:3000` и открывает окно Buzz. При первом
запуске пройдите онбординг: приложение создаст ключ (вашу личность).

Команды по отдельности, если нужно: `just relay` запускает только relay,
`just desktop-dev` — только фронтенд в браузере, но без Tauri он не работает.

## 4. Стать администратором сообщества

CRM-пространство может создать только owner или admin сообщества. Локально это
делается одной командой.

1. В приложении откройте свой профиль (аватар в сайдбаре) и скопируйте свой
   `npub…`.
2. Во втором терминале в папке репозитория выполните:

   ```bash
   . ./bin/activate-hermit
   set -a; source .env; set +a
   cargo run -p buzz-admin -- add-member --pubkey npub1… --role admin
   ```

## 5. Что посмотреть в приложении

1. В сайдбаре нажмите **CRM**. Откроется форма **«Создать CRM-пространство»**.
2. Оставьте «Создать новый закрытый канал «crm»», при желании поменяйте название
   основного склада и нажмите **Создать CRM**. Кнопки нет, если вы не
   администратор сообщества: тогда вместо формы будет «Попросите администратора
   сообщества создать CRM-пространство» (см. шаг 4).
3. **Настройки**: поменяйте часовой пояс, режим фискализации или НДС по
   умолчанию и сохраните. Добавьте склад,
   переименуйте его, сделайте основным, отправьте в архив.
4. **Товары** (ветка `crm/catalog`):
   - «Добавить товар»: название «Кефир», артикул `KFR-1`, цена `1 234,50`.
     В таблице появится `1 234,50 ₽` и `НДС 22%`.
   - Цена `12,345` — появится ошибка «Не больше двух знаков после запятой.»,
     сохранение не произойдёт.
   - Второй товар с артикулом `KFR-1` — диалог останется открытым с сообщением
     «Артикул «KFR-1» уже используется другим товаром.»
   - Поиск по части названия или по началу артикула.
   - «В архиве» → товар пропадёт из списка; включите «Показать архивные», и он
     вернётся с отметкой.
5. **Права**: пригласите другого пользователя в канал `crm` как `member`. Он
   увидит CRM, сможет вести товары, но не настройки и склады. Гость (`guest`)
   видит всё только для чтения.

## 6. CLI (для агентов и проверок)

```bash
cargo build -p buzz-cli
export BUZZ_RELAY_URL=http://localhost:3000
export BUZZ_PRIVATE_KEY=<nsec или hex ключа>   # ключ участника канала crm

./target/debug/buzz crm space show
./target/debug/buzz crm products list --query кефир
./target/debug/buzz crm products create --channel <id канала crm> \
  --name "Молоко 3,2%" --price 89.90 --barcode 4006381333931
./target/debug/buzz crm products archive --channel <id> --product <id товара>
```

Новый ключ можно сделать командой `cargo run -p buzz-admin -- generate-key`.
Чтобы этот ключ видел CRM, добавьте его в канал `crm` из приложения.

## 7. Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| «Community connection failed» | relay не запущен или порт 3000 занят: `just ps`, затем перезапустите `just dev` |
| В CRM написано «Попросите администратора сообщества создать CRM-пространство» | не выполнен шаг 4 или скопирован чужой `npub`; после команды откройте CRM заново |
| Ошибки миграций после смены ветки | `just migrate`; если не помогло, `just reset` (удалит локальные данные) |
| `401 UNAUTHORIZED` при скачивании `quay.io/minio/...` | см. обход в разделе 2 (образ MinIO с ghcr.io) |
| Нужно остановить контейнеры | `just down` (данные сохраняются) |

Автоматические проверки те же, что гоняет агент:

- `cargo test -p buzz-crm`;
- `just test` — Postgres-тесты и e2e, нужен запущенный Docker;
- `cd desktop && pnpm test && pnpm test:e2e:smoke`.
