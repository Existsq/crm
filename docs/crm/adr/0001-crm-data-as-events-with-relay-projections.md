# ADR-0001: Данные CRM — подписанные события с проекциями в relay

- **Статус:** принято
- **Дата:** 2026-09-27

## Контекст

Buzz хранит всё как Nostr-события, а relay — «труба, не мозг» (VISION.md).
Складскому учёту нужны атомарные проверки: нельзя продать больше, чем есть на
складе, и себестоимость должна пересчитываться вместе с движением. Обычные
REQ-фильтры по произвольным тегам фильтруются после `LIMIT` и не подходят для
аналитики. Addressable-события (30000–39999) заменяются по автору, поэтому два
сотрудника, правящие один товар, получили бы две «текущие» версии.

## Решение

- Все изменения CRM — **обычные хранимые события** в блоке kind `42100–42199`,
  с тегом `h` канала CRM-пространства.
- Relay обрабатывает их отдельной веткой ingest по образцу реакций: валидация,
  авторизация и доменные изменения выполняются **в одной транзакции** с
  записью события, затем событие рассылается участникам канала.
- Relay поддерживает таблицы-проекции `crm_*` (товары, контрагенты, остатки,
  движения, документы, фискальные чеки). Мастер-данные обновляются через CAS
  по тегу `expected-revision`.
- Чтение списков, остатков и аналитики — через авторизованные `GET /crm/...`
  (как `GET /workflows/{id}/runs`).
- Ключ идемпотентности — UUID сущности или документа, а не id события: relay
  отвергает события с отклонением времени больше ±900 с, и повтор приходится
  переподписывать.

## Альтернативы

- **Только события, всё считает клиент** — нет атомарной проверки остатка,
  аналитика по тегам неполная.
- **Command kind (как воркфлоу)** — доменные записи идут вне транзакции события,
  а само событие не рассылается.
- **Отдельный HTTP CRUD без событий** — противоречит принципу «предпочитай
  события», теряются подписи, история и realtime.

## Последствия

- Relay получает доменную логику склада — это явное отступление от VISION.md,
  его нужно упоминать в PR.
- Каждая новая таблица соблюдает правила мультитенантности: `community_id`
  первым в ключах, `attach_community_write_fence`, манифесты удаления.
- Документы задним числом не пересчитывают себестоимость уже проведённых продаж.
